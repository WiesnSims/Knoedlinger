# UI style

The rules every Knödlinger screen follows (HUD, menus, overlays). The look: **dark translucent panels,
one warm accent, bright icons, very little text.** References: Megabonk's upgrade screen (framed
panel with a title bar, inventory left, stats right, rows with icon + one stat change) and Vampire
Survivors' level-up (one panel owns the screen, "New!" plus one line per choice).

Every new UI must follow this file and use `ui/theme.tres`. After any UI change, run
`tools/ui_shots.ps1` and look at the shots at 1920x1080 and 1280x720 before calling it done.

## 1. Theme, not overrides

- One theme: `ui/theme.tres`, set project-wide (`gui/theme/custom`). It is generated by
  `tools/ui/make_theme.gd` (`godot --headless --path . -s tools/ui/make_theme.gd`); change the
  generator, then regenerate. Never edit colours or sizes in a UI script.
- **No `add_theme_*_override()` in UI code.** A node picks its look with `theme_type_variation`
  (table below). Custom-drawn widgets read colours with `get_theme_color(name, "Palette")` and font
  sizes with `get_theme_font_size(name, "Palette")`. `tests/unit/test_ui_style.gd` fails on any override
  in `scripts/ui/`.
- The UI is laid out for **1280 x 720** and scales with the window (`canvas_items` stretch, `expand`
  aspect). All numbers below are in those base pixels.

## 2. Spacing: 8 px grid

- Every margin, gap, size and offset is a multiple of 8 (4 is allowed only inside small widgets: pips,
  keycaps, icon insets).
- Steps: **8** (inside a row), **16** (between rows, panel padding, screen margin of the HUD),
  **24** (between panel sections), **32** (between panels).
- HUD widgets sit **16 px from the screen edges**.

## 3. Type: two fonts, three sizes

| Role | Font | Size | Variation |
| --- | --- | --- | --- |
| Small: labels, details, counts | Nunito Bold | **14** | `LabelSmall`, `LabelMuted` |
| Body: names, buttons, stats | Nunito ExtraBold | **20** | `Label` (default), `LabelAccent` |
| Display: titles, the timer, big numbers | Grenze Gotisch (titles), Nunito Black (numbers) | **32** | `LabelTitle`, `LabelNumber` |

- Grenze Gotisch (the "Fraktur-ish display font", GAME-DESIGN.md) is for titles only, never for
  numbers or sentences.
- The one exception to three sizes is the logo on the title screen (`TitleLogo`): a drawn graphic in
  Grenze Gotisch at 88 px, the way a logo image would be. No other text is drawn outside the theme.
- HUD text over the 3D world gets a soft shadow (`Hud*` variations), never a thick outline.
- Fonts live in `assets/fonts/` (OFL, licences next to them).

## 4. Palette

| Token (`Palette`) | Use | Value |
| --- | --- | --- |
| `panel` | every panel, 88 % opaque | `#12141A` @ 0.88 |
| `panel_raised` | rows, slots, buttons on a panel | `#1E222B` @ 0.92 |
| `line` | 1 px panel borders, dividers | white @ 0.10 |
| `text` | main text | `#F5F1E8` |
| `muted` | secondary text, labels in stat lists | `#9A9AA6` |
| `accent` | **the one accent**: focus, selection, XP, "Neu!", key numbers | `#FFC94A` (Knödl gold) |
| `danger` | **Krampus red, only danger**: enemy attacks, low HP warning, boss bar | `#E5383B` |
| `hp` | health fill (Lebkuchen rose) | `#E9738B` |
| `rarity_0..3` | rarity **as a border colour only** | Gewöhnlich `#B8B8C0`, Fein `#5CCB6B`, Edel `#4AA3FF`, Hofratswürdig `#B57BFF` |
| `evolution` | evolution cards and items | accent gold |

- Nothing friendly may use Krampus red; red never means rarity or reward.
- Rarity is shown by the **border** (2 px; 3 px when focused) and a thin glow, never by tinting the
  whole card. The rarity name only appears in the details.
- Icons are the only saturated colour on a panel.

## 5. Text budget

- **Permanent HUD: numbers and icons only, no sentences.** At most one short label per widget.
- A card: name (1 line), one change line (max ~24 characters: "+15 % Schaden", "Neu!"), pips.
  The one-liner, the rarity name and the full stat list only on hover/focus, in the panel's details footer.
- A button: verb + count ("Nochmal bitte 3") in the small size, key as a keycap glyph.
- Toasts: max 5 words, gone after 1.6 s.
- Controls help is never permanent: it shows for the first seconds of a run, then fades.

## 6. Layout: HUD only in the corners

| Corner | Widget |
| --- | --- |
| Top left | Health (heart + bar + number), under it the XP Krügerl with the level |
| Top right | Timer (wall clock + time) |
| Bottom right | Knödl size (Knödl disc + mass + tier, Schupfn cooldown ring) |
| Bottom left | free (co-op teammates later) |

- Nothing else is permanent. Temporary, centre-top: the boss bar (only while a boss lives), the
  Formular line (only while it matters). Toasts in the upper middle. World markers (Wirtshaus,
  Stempel, gate, boss) are small icon pills with a distance; the Wirtshaus marker only shows once the
  Knödl is worth cashing in (tier S or more).
- The build, gold and all stats live in the **Inventory / Stats screen** (Tab or I), which also flanks
  the Speisekarte (inventory left, menu centre, stats right) and the end screen (inventory).
- While a full-screen panel is open (Speisekarte, Tab screen, end screen) the HUD steps back
  entirely; the panel is the only thing on screen besides the dimmed game.

## 7. Motion

| What | How | Time |
| --- | --- | --- |
| Panel in | fade + 16 px rise, ease out cubic | 180 ms |
| Cards/rows in | fade + scale 0.96 -> 1, staggered | 180 ms, 60 ms apart |
| Hover/focus | scale 1.03, border brightens | 100 ms |
| Pick | row flashes, menu fades out | 120 ms |
| Bars (HP, XP, boss) | value eases toward the target | 250 ms |
| Toast | pop in (scale 0.9 -> 1), hold, fade | 150 ms / 1.6 s / 400 ms |
| Panel out | fade | 120 ms |

- Sounds: `ui_hover` on hover/focus change, `card` on pick, `menu_open` when the Speisekarte opens.
- Motion never delays input: a card can be picked while it is still animating in.
- Menus run while the game is paused (solo), so tweens use `TWEEN_PAUSE_PROCESS`.

## 9. Building a new screen

1. A `CanvasLayer` whose UI root comes from `UiStyle.root(self)` (themed, full screen).
2. Panels are `UiStyle.panel()`, text `UiStyle.label(&"<Variation>", tr("KEY"))`, rows and columns
   `UiStyle.hbox/vbox(&"Row16" | &"Gap16" ...)`, buttons `ActionPill`.
3. A new look = a new variation in `tools/ui/make_theme.gd`, regenerate, then use it. Never a colour
   or size in the screen's script (palette colours via `UiStyle.color()` only for drawn widgets).
4. Shots with `tools/ui_shots.ps1` (add the screen as a scene there), check them against this file.

## 10. Checking it

- `tools/ui_shots.ps1 -Name <label>`: HUD, busy HUD (10:00+), Speisekarte with a hovered row,
  Inventory/Stats, end screen, at 1920x1080 and 1280x720, into `build/shots/ui/<label>/`.
- Look at every shot and check it against this list: corners only, 3 sizes, 8 px grid, no red
  except danger, rarity readable from the border, nothing overlaps, readable at 720p.
- The shots also fail at 150 draw calls or more (the web budget counts the UI too).

## 11. Draw calls

The UI shares the < 150 draw-call budget with the game, and in co-op a menu stays open over a
running crowd. In the Compatibility renderer the 2D batch breaks on every texture or font change,
every StyleBoxFlat panel is a draw call of its own and every clipped control (`clip_text`,
`clip_contents`, scroll containers) one more. So:

- No `clip_text`; trim long text with `text_overrun_behavior` (ellipsis) instead.
- Many small repeated things (tiles, pips, icons in a grid) are drawn by one control in passes
  (all frames, then all icons, then all numbers), like `TileGrid`; icons come from the icon atlas
  (`UiStyle.atlas_icon`).
- Never draw a full-screen panel and the full HUD at once: the HUD stays hidden until a panel has
  faded out completely.
