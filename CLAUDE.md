# Knödlinger

3D survivors-like (roguelike, auto-attacks, hundreds of enemies, constant level-ups) set in an Austrian village apocalypse. Solo or online co-op with 1–4 players; solo is fully supported. The twist: your XP is a physical Knödl that rolls behind you on a string, grows, crushes enemies, can be thrown (Schupfn) and cashed in at a Wirtshaus.
Godot 4 (latest 4.x stable, at least 4.6) + GDScript, **web build only** (Compatibility renderer / WebGL2, single-threaded export), hosted on Cloudflare Pages.

The full game design is here and must be followed:
@GAME-DESIGN.md

`docs/DECISIONS.md` records every decision and change made along the way – what the owner decided, what Claude chose, and why (newest at the bottom). Create it in M0 if it does not exist. Read it at the start of a session before changing anything; GAME-DESIGN.md says what the game is, DECISIONS.md how we got there and the exact numbers.

## Code conventions
- GDScript with static typing everywhere (`var speed: float = 5.0`, typed function signatures).
- Code, comments, file and node names in English. Player-facing text in German/Austrian dialect, always through the translation system (`tr()` + `i18n/*.csv`), never hard-coded.
- snake_case files and functions, PascalCase classes and nodes.
- Characters, weapons, passives, evolutions, Knödl sorts, enemies, waves and quests are data-driven `Resource`s (`.tres`) in `data/`. All balance numbers live in `data/balance.tres`. Adding content must not require code changes.
- No real people, brands or band names in any content (see humour rules in GAME-DESIGN.md).
- Every gameplay feature must work in both solo (host only) and co-op – solo is just a host with zero clients.

## UI rules
- Every session follows `docs/UI-STYLE.md` for any UI work (HUD, menus, overlays, new screens): the one theme `ui/theme.tres` (generated by `tools/ui/make_theme.gd`), `theme_type_variation` instead of per-node overrides (`tests/unit/test_ui_style.gd` enforces it), 8 px grid, 3 font sizes, one accent, Krampus red only for danger, rarity as border colour, permanent HUD only in the corners.
- After every UI change, check it by screenshots: web export, then `tools/ui_shots.ps1 -Name <label>` (1920x1080 and 1280x720), look at every shot yourself, critique it against UI-STYLE.md and the references, and iterate until it is clean. Show the owner before/after shots.

## Networking rules
- Host is authoritative for world state (enemies, Brösel, Knödl physics, bosses, timer, chests, Wirtshäuser, damage). Each player owns their own input and character movement; the host validates.
- All gameplay talks to the `NetworkManager` autoload; transport code lives only in `net/`. No gameplay code may assume a single local player.
- Enemies are synced as compressed snapshots of the packed arrays (~15 Hz, unreliable channel), spawns/deaths as reliable events. Budget: < 60 KB/s per client at 500 enemies.
- Browser transport: reuse Berghittn's solution; otherwise `WebRTCMultiplayerPeer` + a signaling server on Cloudflare (Worker + Durable Object) that hands out 4-letter room codes.
- Keep a WebSocket backend working at all times – it is the main way to test multiplayer headless without browsers.
- Room codes and the handshake always carry `game=knoedlinger` and `ver=<version>`; reject mismatched versions.
- Versioning: `application/config/version` in `project.godot` is the only source (HUD, handshake, Ehrentafel). Semantic versioning: features/content raise the minor (1.1.0), fixes/balance the patch (1.0.1). Raise it with every production release.
- Never add a paid service (e.g. a TURN relay) without asking me first.

## Performance rules (web, non-negotiable)
- Enemies are data, not nodes: packed arrays in `EnemyManager`, rendered with one `MultiMeshInstance3D` per enemy type. Never one `CharacterBody3D`/`RigidBody3D` per enemy.
- Collisions between enemies, projectiles, Brösel and the Knödl go through the spatial hash grid, not the physics engine. Jolt physics only for player, Knödl and terrain.
- Projectiles, Brösel, damage numbers and VFX are pooled. No `instantiate()`/`queue_free()` in hot paths.
- Fodder animation in the vertex shader; skeletons only for player and bosses.
- Budgets: desktop browser 60 fps with 500 enemies + 300 projectiles; mobile browser 30 fps with 200 enemies; < 150 draw calls.
- Only use features the Compatibility renderer supports (no compute shaders, no Forward+-only effects). Test in the actual web export, not only in the editor.
- No C#, no GDExtension, no threads in the web build.

## Hosting rules (Cloudflare Pages)
- **No file in the deploy folder may exceed 25 MiB.** Check this on every export; the build script must fail if any file is larger.
- Keep the `.pck` small by design (low-poly vertex-coloured models, OGG audio, no large textures). Target < 15 MiB.
- Single-threaded export, so no COOP/COEP headers are required. Cache headers go in `_headers`.
- Save data lives in `user://` (IndexedDB in the browser) and must also be exportable/importable as a code.

## Commands
Scripts in `tools/` are created during M0 (PowerShell, logs in `build/logs/`, exit code 1 on any error or warning). Keep this list up to date when you add or change scripts.
- Run tests: `godot --headless -s addons/gut/gut_cmdln.gd -gdir=res://tests -gexit`
- Export web build: `godot --headless --export-release "Web" build/web/index.html`
- Local multiplayer test: start one instance with `-- --net=ws --host` and others with `-- --net=ws --join=127.0.0.1` (straight into the run); add `--lobby=<clients>` to the host and `--lobby` to the clients to meet in the co-op room first (the host starts once that many clients are in). Over the relay: `--net=relay --host` / `--net=relay --room=KNDL`, `--relay=ws://127.0.0.1:8790` for a local one
- Scripts (built in M0 unless marked; all take `-Url <preview url>` where a browser is involved):
  - `tools/run_tests.ps1` – GUT tests
  - `tools/build_web.ps1` – import, web export to `build/web/` with the shell `web/shell.html` (loading screen), gzip + split the wasm (Berghittn's `pack_wasm.mjs`), rename the engine files to `k-<hash>.*` (cached for a year by `_headers`), fill the shell's text from `i18n/strings.csv`, fail if any file > 25 MiB or a placeholder is left
  - `tools/browser_check.ps1 [-Browser msedge|firefox] [-Url <url>] [-Scene run|stress] [-Query quality=low]` – serve `build/web/` locally (or use `-Url`), load it in headless Edge via Playwright, the bot plays a run with 500 enemies for 60 s, fail on any console error or fps below budget, screenshot to `build/shots/`; `-Query` adds URL options
  - `tools/stress_test.ps1 [-Enemies 500] [-Projectiles 300] [-Browser msedge,firefox] [-Url <url>] [-Native]` – M0 scenario in Edge + Firefox, reports fps, frame times, draw calls and ms per system to `build/perf/`
  - `tools/mp_test.ps1 -Clients 3` (add `-HostLeavesFirst` for the host-quits case, `-Scene stress` for the M0 arena, `-StartTime 595` to play the real timeline from 9:55 instead of holding 500 enemies: bosses, attack marks, the Formular, loot; `-Lobby` to meet in the co-op room first (different Knödlinger per player); `-Coop` (M6, use 3 clients) for the co-op rules through the room: the host's drill knocks a client down and rolls two Knödl together, Familienstreit at 0:30, Doppelportion for all – checks revives, passes, merges, the Familienstreit and every second Knödl on each client) – headless WebSocket host + clients play a run with bots; checks enemy sync, bandwidth, world states, the Brösel mirror, every Knödl shown, no rejected poses, Speisekarte offers reaching each client (who levels up), run events (attack marks, loot) reaching each client, the enemy lines the host picked reaching each client, version refusal and that no client errors
  - `tools/autoplay.ps1 [-Runs 3] [-Seed 1] [-Character ferdl] [-Map kirtag] [-Grant 1]` (M2, map/Grant M5) – balance log: the bot plays whole 15-minute runs headless at fixed 60 Hz steps (about 2 min each), one JSON per run in `build/balance/<stamp>/` (time, level times, knock-downs, cash-ins, kills, Knödl mass eaten, Stempel, bosses beaten, result, build) and a table; the bot gets back up after a knock-down (`respawn`); fails on errors or a run that misses Sperrstund'
  - `tools/maps/make_kirtag.gd` (M3) – lays out the Kirtag map and saves `data/maps/kirtag.tres` (checks overlaps): `godot --headless --path . -s tools/maps/make_kirtag.gd`
  - `tools/maps/make_gamskogl.gd`, `tools/maps/make_gemeindebau.gd` (M4) – lay out the Gamskogl-Piste and the Gemeindebau-Hof (`data/maps/<id>.tres`, overlap check, shared helpers in `tools/maps/map_kit.gd`): `godot --headless --path . -s tools/maps/make_gamskogl.gd`
  - `tools/audio/make_audio.mjs [--only=kirtag,coin]` (M3) – synthesises the music and sound effects to `assets/audio/` (OGG, deterministic): `cd tools/audio && npm install && node make_audio.mjs`
  - `tools/audio/make_barks.ps1` (M3) – placeholder voice barks with the Windows de-AT text-to-speech voice (`assets/audio/sfx/bark_*.ogg`, `mahlzeit.ogg`)
  - `tools/audio/voices/voices.py [voice_<enemy>_<line> ...] [--samples]` (1.2) – the enemy voice lines (`assets/audio/sfx/voice_*.ogg`), spoken by eSpeak NG and filtered per voice (Berghittn's Gredn pipeline; needs eSpeak NG and `pip install numpy scipy soundfile`): `python tools/audio/voices/voices.py`. - Browser URL options mirror the command line: `index.html?enemies=200&bot=1`. A plain URL opens the main menu; any run option starts the run directly (`scene=stress` for M0's arena; `mute`, `debug`, `log_slow`, `room=KNDL` (invite link: joins that co-op room after the name prompt), `coop=1` (menu on "Stammtisch aufmachen") and `relay=<ws url>` (a test relay) alone still open the menu). Run flags: `bot=1` (the bot plays), `debug=1` (F3 overlay on), `god=1`, `knodl_mass=500`, `enemies=500` (hold a fixed crowd), `character=ferdl`, `seconds=60` (print a [RESULT]), `start_time=880` (start the clock late), `autoplay=1 runs=3 out=<dir>` (balance log, desktop), `debug=0` (overlay off even with the bot), `pick_delay=90` (the bot waits before it picks, for screenshots), `map=kirtag` (or `gamskogl`, `gemeindebau`, `testfeld`), `weapons=hagelkanone,sachertorte` (extra start weapons, testing), `items=doppelportion` (start items, testing), `net=relay&host=1&lobby=3` / `net=relay&room=KNDL&lobby=1` (co-op room in the browser, used by `mp_tabs.mjs`), `coop_drill=1` and `streit_at=30` (host test hooks for `mp_test -Coop`), `grant=1` (Grant level index, 0 = Gemütlich .. 4 = Weltuntergang), `respawn=1` (knocked down = back at the spawn instead of the run ending; the automated checks use it), `mute=1`, `quality=high|medium|low|auto` (automated runs default to high), `touch=1` (touch controls on), `voice_every=1` (an enemy line every second, any type: screenshots).
- Controls: keyboard + mouse, gamepad (Xbox layout: left stick, right stick looks, A jump, RB/RT Schupfn, Start pause, Back inventory, X/Y/LB reroll/banish/skip on the Speisekarte, LB/RB and LT/RT page through menus), touch (`TouchControls`). New actions go into `InputSetup` with keyboard and pad events; keycaps use `KeycapLabel`.
- One-time setup: `npm install` in `tools/browser/`, then `npx playwright install firefox` (Edge is used as installed). Set `GODOT` if `godot` is not on PATH.
- Run scripts with `powershell -NoProfile -ExecutionPolicy Bypass -File tools/<script>.ps1`
- Test runs must never disturb the user at the PC: prefer `--headless` and headless browsers. When a visible window is unavoidable, keep it small, unfocused, without mouse capture and muted.
- Before saying a task is done: run the tests, the web export, the browser check and a headless multiplayer test (`mp_test.ps1 -Clients 1` at minimum), and fix any errors or warnings in the output.
